Два сценария, которые решают задачу

Гостевая корзина

Товары, выбранные до регистрации, не теряются.

  1. При первом запуске генерируется UUID сессии и сохраняется на устройстве.
  2. Корзина работает по этому идентификатору — гость может всё, вплоть до заказа.
  3. После входа вызывается POST /cart/merge: корзины объединяются.
  4. Повторный merge защищён ref-ом — срабатывает ровно один раз.

Один код — два транспорта

Web и телефон требуют разного подхода к адресам API.

  1. Web: Metro проксирует /api и /auth-api — для браузера всё same-origin, CORS не возникает.
  2. Native: если в конфиге localhost, приложение берёт IP компьютера из данных Metro.
  3. Для Android-эмулятора — fallback 10.0.2.2.
  4. Разработчику достаточно npm start — адреса подставляются сами.
Отдельно решены изображения: относительные пути достраиваются до нужного origin, внешние CDN на web идут через прокси-ресайз. Данные в базе под мобильное приложение не менялись.

Границы решения и развитие

Что сознательно не вошло

  • офлайн-режим и кэш каталога
  • push-уведомления
  • онлайн-оплата
  • автотесты интерфейса (Detox / Maestro)

Следующие шаги

  • обновление токена без повторного входа
  • кэш каталога и офлайн-просмотр
  • сквозные UI-тесты в CI
  • публикация в Google Play и App Store
Каждое из ограничений — отдельная задача с известным путём решения; на основную бизнес-логику они не влияют: каталог, корзина, заказы и авторизация работают end-to-end.
